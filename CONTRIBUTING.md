# Розробка

Потрібен Node.js 22 або новіший. Для JS-плагіна в Siaivo Node.js не потрібен.

```sh
npm ci --ignore-scripts
npm test
```

Авторський код `siaivo-dorama.js` має залишатися ES5. Сучасний JavaScript дозволений
у Node-тестах. Тести перевіряють ES5 справжнім парсером Acorn.

`d.js` — постійний завантажувач, `siaivo-dorama.js` — повний плагін.
**Не копіюй повний плагін у `d.js`.** Нові версії публікуй за тим самим шляхом
`siaivo-dorama.js` у `main`; постійна коротка адреса — `https://da.gd/siaivod`.
Маркери заголовка плагіна й `PLUGIN_ID` використовуються для перевірки відповіді;
regression тест перевіряє, що завантажувач приймає справжній поточний плагін.
Зміни завантажувача потребують ES5-тестів та браузерної перевірки старту,
оновлення через перезапуск і резервного кешу.

Після успішних regression jobs CI примусово очищає CDN й перевіряє актуальність
відповідей. Якщо `refresh-cdn` впав, перевір причину і повтори job; не оголошуй
доставку перевіреною лише через успішний push. Ручна команда для опублікованого
актуального `main`: `node scripts/refresh-cdn.cjs`. Вона не призначена для
неопублікованих локальних змін: перевіряє CDN побайтово з локальним checkout.
Докладніше: [доставка](docs/DELIVERY.md).

CI запускає `refresh-cdn.cjs --force`: свіжа відповідь одного CDN-вузла не
доводить свіжість усіх інших вузлів. CDN-очищення не видаляє кеш пристрою.
Для перевірки HTTP-кешу використовуй `npm run test:delivery-cache` з Chromium
(можна передати `SIAIVO_CHROMIUM_PATH`). У цьому тесті немає Playwright routing:
перехоплення запитів вимикає браузерний HTTP-кеш і приховує саме цей дефект.

Для браузерної перевірки див. [опис аудиту](docs/AUDIT.md). На GitHub її можна
запустити вручну: Actions → Siaivo browser smoke → Run workflow.

Під час змін зберігай окремий розділ «Дорами» в лівому меню, штатні category /
category_full / full і TMDB source карток. Не додавай рядки на головну й не патч
глобальні API або фільтри Siaivo без окремо обговореної потреби.

До pull request додавай опис поведінки, результати перевірок і запис у CHANGELOG,
якщо змінено плагін. Після оновлення JS перезапускай Siaivo повністю.

Для змін добірок перевіряй `tests/selection.test.js`: п'ять популярних країн,
одна спільна ЛГБТ-добірка, одна загальна добірка новинок, `popularity.desc`,
відсутність меж дат і порогів в основних популярних та ЛГБТ,
шестигодинний кеш та відсів аніме й підтверджених не-дорам.
Не повертай обмеження року або retired genre/network/airing routes.
Keywords та помилково класифіковані ID перевіряй через TMDB API; не визначай
тип або ЛГБТ лише за словами у назвах. Не виключай спортивні ігрові дорами
за загальним тегом wrestling: він є також у серіалах про спортсменів.
Публічний `Utils.isAnime` у Siaivo має евристику японської мови на холодному
старті: передавай лише TV-ідентичність для перевірки карти, а не всю японську
картку. Серверні жанри й keywords мають працювати й без готової карти.
Фіксована 2:1 пагінація основних добірок повинна лишатися стабільною.
Дата маршруту лише для новинок обмежує вікно першої прем’єри; інші добірки не обмежує.

Новинки, додані за запитом користувача, перевіряються в `tests/newest.test.js`:
120 днів до дати маршруту включно, popularity ≥ 10, ≥ 3 оцінки, KR/CN/JP/TH/TW.
Перевіряй точну компактну пагінацію 40, дедуплікацію, межу 5 raw pages / 100
карток, 3-годинний кеш, одночасні звернення, clear, помилки без часткового кешу
й фіксацію мови/дати. Поріг популярності — параметр відбору, не оцінена
ймовірність перекладу: при зміні переперевіряй живі вибірки, не вигадуй гарантій.
Збережи ліниві перші чотири популярні країни, щоб побудова новинок не затримувала їх.
Поточні результати й обмеження: [аудит новинок 0.8.0](docs/NEWEST-AUDIT.md),
[метрика популярності](docs/POPULARITY-AUDIT.md).
