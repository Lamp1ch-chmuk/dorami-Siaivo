# Постійна адреса й оновлення плагіна

Постійний URL: **https://da.gd/siaivod**. Прямий URL:
`https://cdn.jsdelivr.net/gh/Lamp1ch-chmuk/dorami-Siaivo@main/d.js`.
З 0.5.1 це завантажувач. Нові релізи не потребують нових скорочень.

## Одноразовий перехід

Якщо вже встановлено постійний URL, його змінювати не потрібно. Якщо встановлено
коротку адресу `siaivod5` або JS за тегом версії, заміни той запис на постійний
URL один раз. Прибери інші записи цього самого плагіна й повністю перезапусти
Siaivo: старий плагін у тій самій сесії не може бути безпечно замінений.

**Повний перезапуск сам по собі не очищає HTTP-кеш пристрою.** Під час переходу
зі старого повного JS на завантажувач браузер може ще показувати 0.4.1:
jsDelivr повертає `Cache-Control: public, max-age=604800, s-maxage=43200` —
7 днів клієнтського кешу й 12 годин спільного кешу. Скорочувач не передає
`reset` у Location, тому випадковий параметр Lampa не змінює кінцевий URL.
Серверне очищення CDN не може видалити вже збережену браузером відповідь.

У комп'ютерному браузері одноразово застосуй **Ctrl+Shift+R / Ctrl+F5**.
Після цього заголовок буде `Siaivo Dorama permanent loader v1`. Номер версії
повного плагіна знаходиться в `siaivo-dorama.js`, а не у заголовку завантажувача.
Якщо проблема підтвердиться на ТВ, потрібне оновлення саме HTTP-кешу браузера
або WebView; звичайна кнопка очищення даних Siaivo не є доказом цього й не
рекомендована як універсальний спосіб. Налаштування та список плагінів не треба
скидати, нову коротку адресу створювати не потрібно.

## Як надходить новий код

1. Штатний завантажувач плагінів Siaivo відкриває коротку адресу.
2. `d.js` отримує `siaivo-dorama.js` із `raw.githubusercontent.com`, гілка `main`.
   Кожний повний запуск додає новий параметр свіжості. Немає версій у цьому URL,
   запитів тегів/релізів GitHub API або фонових таймерів оновлення.
3. Відповідь читається як текст і виконується як inline script, так само як
   нативний кеш плагінів Lampa. Прямий Raw URL не можна ставити як plugin URL:
   GitHub віддає його з `text/plain` і `nosniff`, що забороняє script-src загрузку.
4. Перевіряються маркери плагіна й розмір відповіді. HTML/HTTP-помилки не
   виконуються й не замінюють кеш. HTTPS-перевірка лишається ввімкненою.
5. Отриманий код зберігається лише в приватному ключі
   `siaivo_dorama_loader_code_v1` у localStorage. За недоступності оновлення
   запускається останній збережений код. Якщо кешу ще немає, виконується один
   резервний CDN-запит. Запити мають 10-секундний timeout і 12-секундний запобіжник.

Типовий запуск додає один запит коду. Повторне включення завантажувача в тій
самій сесії нічого не дублює. Аргументи email/origin, які Lampa додає до короткої
адреси, не передаються в запити GitHub Raw чи резервного CDN.

## Публікація

Редагуй повний плагін у `siaivo-dorama.js`; **не перезаписуй ним `d.js`**.
Після push у `main` усі regression jobs повинні пройти. Job `refresh-cdn`
перевіряє, що checkout ще є актуальним `main`, і запускає `scripts/refresh-cdn.cjs`.
CI запускає скрипт з `--force`: очищає обидва CDN-файли й повторно звіряє їх
побайтово. Без `--force` локальна команда може пропустити очищення, якщо її
CDN-вузол уже актуальний; це не доводить стан інших вузлів. Помилка доставки
є помилкою job, а не тихим успіхом.

Це допомагає початковому переходу на завантажувач та рідкісним змінам самого
завантажувача. Наступні зміни повного плагіна отримуються через Raw, навіть якщо
CDN ще зберігає попередній завантажувач. Теги для архіву можна створювати; вони
не змінюють адреси підключення.

## Перевірки та межі

`npm test` перевіряє ES5 й 11 сценаріїв завантажувача. `npm run test:browser`
використовує незмінену Siaivo та її штатний список плагінів: початковий запуск,
повторне включення, новий код після перезапуску за тим самим URL і запуск
останнього збереженого коду без мережі. Відповіді коду/TMDB у браузерному smoke
підставлені. Після публікації окремо перевіряються справжні HTTP-відповіді,
короткий редирект і байти коду.

Окремий `npm run test:delivery-cache` відтворює 7-денний HTTP-кеш у справжньому
Chromium без перехоплення запитів. Після зміни відповіді сервера новий короткий
URL із `reset` все одно запускає 0.4.1. Hard reload отримує 0.5.1 за тією самою
адресою, й наступний звичайний запуск теж використовує нову відповідь.
Звичайний UI smoke має Playwright routing, який вимикає HTTP-кеш: він не міг
підтвердити перехід для пристрою, що вже кешував старий повний JS.

Перевірено після публікації 0.5.1, 2026-10-02: постійний короткий URL повернув
HTTP 200 `application/javascript`; тіло побайтово збіглося з `d.js`. Запит із
параметрами `logged/reset/origin` також повернув той самий завантажувач. Живий
GitHub Raw повернув точний актуальний `siaivo-dorama.js`. CI коміту `ab204bf`,
включно з `refresh-cdn`, пройшов; ручна перевірка обох CDN-файлів теж пройшла.

Час доступності на конкретному ТВ не гарантується: пристрій, DNS і сервіси
можуть мати свій кеш або бути недоступними. Після успішного оновлення адреса
лишається тією самою між релізами. Офлайн-код може бути старішим; на першому
офлайн-запуску без кешу плагін не завантажиться. Оновлення коду потребує повного
перезапуску; поточні добірки TMDB окремо використовують свої TTL.

Поточний реліз каталогу — 0.7.0; постійний URL та loader v1 збережено.
Правила добірок і перевірки: [аудит 0.7.0](POPULARITY-AUDIT.md).
